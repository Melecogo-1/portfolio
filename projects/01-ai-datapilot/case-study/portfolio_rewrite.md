## 二、核心项目：电商销售数据分析案例研究（新增，P0）

### 项目标题
用AI辅助发现20亿销售数据中的业务问题

### 项目副标题
电商多品类销售数据分析 — 从原始Excel到可执行的业务洞察

### 项目概述
基于某电商公司20.15亿真实销售数据（28.4万台PC + 4.9万条O2O订单 + 15.6万条账单），用AI辅助分析发现了10个业务问题，其中2个严重、5个警告。建立了"人主导+AI辅助+人工验证"的分析方法论，总结了5个降低AI出错概率的方法，记录了4个AI出错案例及纠正过程。

### 核心亮点（用具体证据，不用概念）
1. **真实数据驱动**：不是模拟数据，是20亿真实营收、4.9万条真实订单
2. **AI做计算，人做决策**：明确区分AI的角色（批量计算、初步筛选）和人的角色（定义分析维度、验证结论、给出可执行建议）
3. **完整验证过程**：每个关键结论都有验证步骤——定位原始数据单元格、手动计算交叉验证、检查数据口径、确认AI没有幻觉
4. **AI出错案例**：记录了4个AI错误（把"报价未成交"误判为"数据质量问题"、建议过于笼统、API余额不足、混淆毛利率口径），展示了我如何发现和纠正
5. **可交付产物**：案例研究HTML页面 + 数据分析报告 + Flask可交互原型（附加产物）

### 关键发现（3个最有价值的）
1. **快手平台毛利率-1.70%，亏钱在卖**（严重）：收入仅26万，客单价2741元（远低于整体7084元）。验证：定位到分平台汇总sheet快手行，手动计算交叉验证。建议：设定亏损上限5万和时间窗口3个月。
2. **44%订单"缺成交价"，实为"报价未成交"**（信息）：AI一开始误判为"数据质量问题"，我深入分析状态分布发现100%都是未成交状态。"撤销"=报价未成交，不是退货。建议：管报增加"报价→成交转化率"指标。
3. **小米报价量最大（12,723次）但成交率仅15.4%**（警告）：荣耀成交率69.7%，是小米的4.5倍。10,767次无效报价占用大量销售人力。建议：小米只对有价格优势的SKU报价，计算各品牌报价人力成本。

### 技术栈
Python + pandas + DeepSeek AI + Flask + ECharts

### 交付物

## 三、Creative Engine Lab（重写）

### 原定位
AIGC创意工具 — Midjourney提示词管理和生成

### 新定位（FDE视角）
**AI创意生产流水线 — 把Prompt工程变成可复用的创意生产工具**

### 重写后的描述
这是我在实际AIGC创作过程中遇到的痛点驱动的项目。当时的问题是：每次做图都要重新写Prompt，好的Prompt散落在各个聊天记录里，无法复用和迭代。

**我的决策：** 不做一个"通用AI绘画工具"（那是Midjourney的事），而是做一个"创意生产流水线"——把我验证过的Prompt、风格参数、参考图组合成可复用的模板，让创意生产从"每次从零开始"变成"基于模板快速迭代"。

**AI的角色：** 负责根据用户输入的创意关键词，匹配对应的Prompt模板并生成变体。AI不做创意决策，只做模板匹配和文本生成。

**人的角色：** 定义创意分类体系、验证每个Prompt的输出质量、决定哪些Prompt可以进入模板库、判断AI生成的变体是否可用。

**核心功能：**
- 创意模板库：按风格/题材/用途分类的可复用Prompt模板
- AI变体生成：基于模板生成多个Prompt变体，快速探索创意方向
- 参考图管理：把验证过的参考图和Prompt绑定，形成完整的创意资产
- 生产记录：记录每次生成的参数和结果，方便回溯和迭代

**技术栈：** Python + Flask + DeepSeek API + SQLite + 前端交互

**项目亮点：** 不是"用AI做图"，而是"把AI做图的过程工具化"。解决的是真实的创作效率问题，有明确的使用场景和可衡量的效率提升。

## 四、Provenance Lab（重写）

### 原定位
AI作品溯源工具 — 区块链存证

### 新定位（FDE视角）
**AI资产质量管理工具 — 给AI生成内容建立可追溯的元数据体系**

### 重写后的描述
随着AI生成内容越来越多，一个真实问题浮现出来：哪些图是AI生成的？用了什么Prompt？参考了哪些图？修改了哪些地方？这些信息如果不记录，后续就无法追溯、无法复用、也无法应对版权质疑。

**我的决策：** 不做一个"区块链存证平台"（那太宏大且不实用），而是做一个轻量级的"AI资产管理工具"——给每张AI生成的图片绑定完整的元数据（Prompt、参数、参考图、修改记录），让AI资产可追溯、可检索、可复用。

**AI的角色：** 负责从图片中提取特征、自动识别相似图片、生成内容标签。AI不做版权判断，只做元数据提取和相似度计算。

**人的角色：** 定义元数据标准、判断AI提取的标签是否准确、决定哪些资产需要重点保护、处理版权相关的决策。

**核心功能：**
- 元数据绑定：每张图片绑定Prompt、模型参数、参考图、修改记录
- 相似度检索：基于图片特征快速找到相似作品，防止重复创作
- 版本管理：记录图片的迭代过程，每个版本都可追溯
- 版权声明：一键生成AI创作声明，包含完整的创作过程信息

**技术栈：** Python + Flask + 图像特征提取 + SQLite

**项目亮点：** 解决的是AI时代的真实问题——资产管理和版权追溯。不是概念性的"区块链存证"，而是实用的元数据管理工具。有明确的边界声明（AI只做特征提取，不做法律判断）。

## 五、Dream Weaver（重写）

### 原定位
AI叙事游戏 — 互动惊悚

### 新定位（FDE视角）
**LLM交互系统原型 — 验证自由输入判定+状态管理的技术可行性**

### 重写后的描述
这是一个技术验证项目，目标是验证"用大语言模型驱动的自由交互叙事"是否可行。当时的核心问题是：传统互动游戏的选项是预设的，玩家只能选A或B；如果让玩家自由输入文字，AI能不能理解并推进剧情？同时，怎么管理复杂的剧情状态（角色关系、物品、场景）？

**我的决策：** 不做一个"完整的游戏"，而是做一个"技术可行性验证原型"——用一个短篇故事场景，验证自由输入判定、状态管理、剧情分支三个核心技术点是否可行。

**AI的角色：** 负责理解玩家的自由输入、生成剧情回应、判断玩家行为对状态的影响。AI不做剧情设计，只做自然语言理解和文本生成。

**人的角色：** 设计剧情框架和状态系统、定义AI的行为边界、验证AI生成的剧情是否符合逻辑、决定哪些分支可以保留。

**遇到的问题和解决：**
- **问题1：** AI经常"忘记"之前的状态，导致剧情矛盾。**解决：** 建立独立的状态管理系统，每次对话前把当前状态注入Prompt，AI只负责基于状态生成回应，不负责记忆。
- **问题2：** 玩家输入不合理的行为（比如"我要飞天"），AI不知道怎么处理。**解决：** 增加"行为合理性判定"层，AI先判断行为是否在当前场景合理，不合理就给出合理的拒绝回应。
- **问题3：** AI生成的剧情太发散，无法收敛到预设结局。**解决：** 设计关键剧情节点，到达节点时强制收敛，AI只在节点之间有自由发挥空间。

**技术栈：** Python + Flask + DeepSeek API + 状态管理系统 + 前端交互

**项目亮点：** 不是"做了一个AI游戏"，而是"验证了AI交互叙事的技术可行性，并记录了3个核心问题的解决方案"。展示了我如何定义问题、设计实验、遇到问题、解决问题的完整工程思维。

## 六、沉海遗墟视频制作（重写，弱化）

### 原定位
AI视频作品 — 漫剧第一集

### 新定位（FDE视角）
**AI视频生产工作流 — 分镜驱动+一致性管理+迭代修正的工业化流程**

### 重写后的描述
这是一个AI视频制作的实践项目，目标是用AI工具完成一个短篇漫剧的制作。核心挑战不是"用AI生成视频"，而是"怎么保证多镜头之间的角色一致性、场景连贯性、剧情逻辑性"。

**我的决策：** 不追求"一键生成完整视频"（目前技术做不到），而是建立一个"分镜驱动的工业化生产流程"——先做完整分镜脚本，再逐镜头生成，最后人工审核和修正。

**AI的角色：** 负责单镜头的图像/视频生成、角色参考图匹配、场景生成。AI不做分镜设计和剧情决策，只做单镜头的内容生成。

**人的角色：** 设计分镜脚本、定义角色和场景设定、审核每个镜头的质量、修正AI生成的错误、做最终剪辑。

**核心流程：**
1. 分镜脚本：先完成完整的分镜设计，每个镜头明确景别、运镜、角色动作、台词
2. 角色设定：建立角色参考图库，保证多镜头一致性
3. 逐镜生成：按分镜逐镜头生成，每个镜头多生成几个版本筛选
4. 人工修正：对AI生成的错误（角色变形、场景错误、逻辑矛盾）进行人工修正
5. 剪辑合成：把修正后的镜头合成完整视频，加音效和字幕

**遇到的问题：**
- 角色一致性：不同镜头的角色长相不一致。**解决：** 建立统一的角色参考图，每个镜头都用参考图做图生图，减少自由度。
- 场景连贯性：相邻镜头的场景布局不一致。**解决：** 先做场景设定图，每个镜头都基于同一场景设定生成。
- AI生成的剧情逻辑错误：AI有时候会生成不符合剧情的动作。**解决：** 每个镜头都用详细的Prompt描述角色动作，减少AI自由发挥空间。

**技术栈：** Midjourney / 即梦AI / 剪映 / 人工修正

**项目亮点：** 不是"AI生成了一个视频"，而是"建立了一套AI视频工业化生产流程"。展示了我如何管理AI的输出质量、如何用人工修正弥补AI的不足、如何把复杂的创作过程拆解成可执行的流程。

在重庆云幕科技有限公司完成两个月三维建模与可视化实习，参与城市基建动画和医疗数字沙盘两个项目。

**具体工作：**
1. **重庆曾家岩隧道动画：** 修正主体、匝道与通风设施的穿模、失真问题，精简模型面数并反复适配镜头。在"高精度还原"和"实时渲染性能"之间做平衡，最终模型在保证视觉质量的前提下满足实时展示要求。

**交付结果：** 两个月完成隧道修正与医院整套沙盘交付，**一次性验收通过**。沉淀了模型轻量化流程，缩短了后续项目的渲染调试时间。

**学到的：** 这是我第一次在真实团队中做交付，学到了"客户需求→技术方案→迭代修正→验收交付"的完整流程。特别是"一次性验收"让我理解了：交付不是"做完了"，而是"符合要求、可运行、客户认可"。
